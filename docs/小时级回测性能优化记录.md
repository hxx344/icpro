# 小时级回测性能优化记录

2026-09-07，本机 BTC 45/10 全区间三口径回测从 **54.95 秒降至 22.49 秒**，提速 **2.44 倍**，耗时减少 **59.08%**。三种口径的成交与盈亏结果保持一致。

## 测量条件

- 配置：`configs/backtest/btc_report_ic_45_10.yaml`。
- 区间：2023-03-20 00:00 至 2026-03-24 23:00 UTC。
- 数据：43,771,890 行期权快照、26,422 个有效小时。
- 每次启动独立 Python 进程，已有同区间磁盘缓存；依次执行标记价无费用、盘口扣费、盘口扣费并校验数量三个版本，并导出所有 CSV、JSON、Markdown 和 HTML。
- 总耗时使用 PowerShell `Stopwatch` 测量，包含 Python 启动、导入、数据读取、回测和报表生成。为本机一次前后对照，不代表其他数据规模或无磁盘缓存环境的固定耗时。
- 优化前基于提交 `1df1935`。运行时没有并行执行其他性能测试。

| 项目 | 优化前 | 优化后 | 提速 |
|---|---:|---:|---:|
| 完整三口径回测及报表 | 54.95 s | 22.49 s | 2.44× |
| 43,771,890 行数据的小时索引构建 | 6.41 s | 1.72 s | 3.73× |

第二行单独测试索引函数，不含读取 Parquet 的时间。已有区间缓存命中时无需重建该索引，因此不能将该行节省的时间再加到第一行。

## 瓶颈与修改

先用 `cProfile` 分析优化前的单个盘口数量校验版本，预先完成数据加载。该分析中，循环耗时 26.68 秒，报价查询累计耗时 12.54 秒，单个开仓时间读取原始 Parquet 累计耗时 8.45 秒。分析器本身有开销，此数字不用于计算整套回测提速比例。

1. **按需处理合约报价。** `HourlyOptionStore.get_quote()` 原先每小时对所有挂牌合约逐项检查、转换 bid/ask/mark；现在只建立合约行号映射，对实际查询的持仓合约处理报价，并缓存同小时的重复查询。保留缺失价格回退、重复合约取最后一行、open/close 隔离及原有按合约时间索引行为。
2. **批量预读开仓元数据。** 研究脚本按月一次读取候选周五 21:00、22:00、23:00 的原始报价数量和时间戳，覆盖三个回测版本及事后审计。当前配置由逐个时间读取改为 37 次月度读取。策略仍按当前小时依次决策，不访问未来时点的数据；未预读时点保留直接读取路径。缓存通过源文件路径、修改时间和大小失效，重复快照只在实际查询该时点时才报错。
3. **向量化构建小时索引。** 使用 NumPy 找出小时和快照类型的分组边界，Python 循环只遍历分组，不再逐行遍历数千万条合约记录。磁盘缓存格式未改变，已有缓存可以继续使用。
4. **记录阶段耗时。** 每次研究回测新增 `performance.json`，记录元数据预读、各口径的数据加载、模拟、结果导出及对比图生成耗时。

第一、三项位于共享小时数据层，也作用于其他使用该层的回测；第二、四项用于 `backtest_btc_report_ic.py`。

## 优化后阶段耗时

| 阶段 | 耗时 |
|---|---:|
| 原始元数据预读 | 1.50 s |
| 首个版本加载数据 | 3.60 s |
| 后两个版本加载数据合计 | 0.72 s |

阶段小计存在其他初始化开销与四舍五入差异。

## 一致性与测试

- 优化前后共 27 份结果文件一致：各口径 8 个 CSV 的 SHA-256 完全相同，3 个汇总 JSON 按内容精确相等。
- 核查范围包括逐腿成交、整组交易、小时权益、每日 PnL、分年结果、开仓尝试、原始快照审计和缺失报价记录。
- 盘口数量校验版本仍为 151 组、604 条腿，净盈利 19,001.785502599978 USD；其余两种口径也保持原结果。
- 对完整数据分别执行优化前、后的索引函数，52,844 个分组索引完全相同。
- 41 项相关测试通过，覆盖报价回退、跨小时/快照类型切换、重复合约、缺失报价、缓存源文件变更、批量读取及原始交易账本行为；相关文件 Ruff 错误检查通过。

## 使用与核查文件

无需增加性能开关，继续使用原命令：

```powershell
.\.venv-1\Scripts\python.exe scripts/research/backtest_btc_report_ic.py --config configs/backtest/btc_report_ic_45_10.yaml
```

性能实验保存在 `reports/performance_report_ic/`：

- `before_timing.json`、`after_timing.json`：完整进程计时。
- `before/`、`after/`：两次完整回测的结果。
- `after/performance.json`：优化后的各阶段计时。
- `verification.json`：结果文件校验记录。
- `hour_index_benchmark.json`：完整数据索引函数对照。
- `before_loop.pstats`：优化前循环的性能分析文件。
